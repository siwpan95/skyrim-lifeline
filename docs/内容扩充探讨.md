> 本文档是**提案**，不是已实施内容。基于两件事：① 对本仓 109 场景 / 7 内容包 /
> 状态配置的逐项核对；② 联网检索《生命线》开发者访谈、交互叙事设计文献、
> 上古卷轴世界观考据与同类作品分析。检索日期 2026-11-16。

## 〇、结论先行

本作的地基（玩家只给建议、她会拒绝、Rewind 免费）是站得住的，
真正的短板不在"写得不够多"，而在**三个已承诺但未兑现的机制**和**两条没用满的引擎能力**：

| 缺口 | 现状（可验证） | 为何值得优先 |
|---|---|---|
| **信任不驱动"听不听"** | 加权跳转全是数字字面量（7/3、6/4…），只随**你选了哪句建议**变，与 `trust` 无关（`00-core.yml:152-166`；引擎 `_pick_weighted` 只接受 int/float） | 这是全作的**核心卖点**，却只兑现了一半 |
| **soul 归零无后果** | `soul` 只被 `bounds` 钳到 0，无 fatal、无门控；真结局终局就是 `soul=0` 且照常通关 | README 写"归零即通讯断绝"，机制上没实现 |
| **`@loop` 时间循环完全没用** | `dse.yml` 预留 `loopKeep: [clues, flags]`，引擎已实现 `@loop:` + 跨轮保留知识，本作一处未用 | 这是把 Rewind 从"功能"升级成"叙事主题"的现成杠杆 |
| 成就只有 6 条 | `dse.yml:191-217` | 纯 `when` 表达式，扩展成本极低 |
| `end-dragon-slayer` 缺位 | `docs/design.md` §七待办里就写着 | 已画好的坑，填上即可 |

**建议顺序**：先补"承诺兑现"（P0），再做"剧情纵深"（P1），最后动"结构性大改"（P2）。
不要一上来加新章节——地基没夯实之前，加内容只会放大路径爆炸与门禁成本。

## 一、联网调研得到的设计参照（含出处）

### 1.1 《生命线》原作者的三条忠告

3 Minute Games 访谈（GameAnalytics,
<https://www.gameanalytics.com/blog/lifeline-3-minute-games-interview>）：

- **"Think of dialogue vines, not trees"**——不要疯狂分叉，否则"你会得到 64 个段落却没有一个结局"。
  偏离主线一小段，再编织回主线；**不要把最好的场景藏在小支线里**。
  → 本作 `docs/design.md` §4.5 的"藤蔓结构"已内化这条，扩充时必须继续遵守。
- **约束催生创意**：作者说"我不想让角色有性别、要三天实时、只能给两个选项、只能用对话交流"，
  于是"走路一小时、睡八小时"这些延迟反而成了真实感来源。
  → 本作的约束是**五种固定 mode + 封闭 Schema**，扩机制要在这个笼子里跳舞（见 §三）。
- **选择必须真的有分量，哪怕代价是角色早死**；但也警告"叙事强行转折"（choice 做了却照样发生）会抽空选择的回响。

### 1.2 学术视角：《生命线》的成功与陷阱

《Alive: A Case Study of an AI Conversation Simulator》
（<https://pdfs.semanticscholar.org/77ed/36c69ee06343c1915738ee7f1f32fe95c51f.pdf>）
总结 Short 的批评，几条对本作极有针对性：

- "gauntlet pattern"——主线为主、短分支迅速死亡或回归，是本作现在的形态，OK。
- **多数选择是装饰性的**——但在"以对话本身为目标"的游戏里，装饰性选择因影响对方回应而获得额外重量。
  → 所以本作可以保留大量"措辞不同"的选项，但要让**至少关键节点**的选择改变状态。
- **延迟且不可预测的恶果最令人挫败**：几小时后才发现早先某个选择注定死亡，玩家当时无从判断。
  → 扩充时若要加"隐藏死亡线"，必须给可发现的线索（见 §2.2 不可靠叙述的"公平规则"）。
- **不要加与对话核心无关的系统**——这条直接否掉了"大地图 / 复杂装备 / 语音"等方向。

### 1.3 系统叙事的当代范式：Citizen Sleeper

Eric Deters 的拆解（<https://eric-deters.com/writing/citizensleeper>）与
Noonnoo 的分析（<https://noonnoo.com/?p=828/>）：

- 它的核心是 **Drives（目标）+ Clocks（时钟）+ 骰子（行动力）+ 消耗态（Energy/Condition）**；
  叙事不是"写在分支里"，而是**从系统的稀缺中涌现**。
- "当一个骰子要拿来买食物还是帮朋友时，选择的叙事重量来自系统本身，而不是对白。"
- 关键洞察：**把压力做成可见的系统**，比写十段"她很冷"的文字更有戏剧张力。
  → 本作已有 `clock`（夜深刻度）、`warmth`、`soul`、`trust` 四个天然-pressure 变量，
  但目前只有 `warmth` 是硬死亡线，其余都是"隐性计数器"。可做成**显性时钟**（§3.3）。

### 1.4 不可靠叙述者的工艺

Endless Adventure《谁在说谎？在分支故事中使用不可靠叙述者》
（<https://endlessadventure.io/zh-us/blog/whos-lying-using-unreliable-narrators-in-branching-stories>）
与 Game Developer 的辩护文（<http://www.gamedeveloper.com/design/reliable-story-telling>）：

- **共用锚定场景**：每个分支都出现同一场景，但细节因叙述者不可靠而不同 → 玩家跨周目比对。
- **矛盾的目击者**：同一 NPC 在不同分支给出不同反应，动摇可信度。
- **保留情感真相**：即便事实模糊，背叛/自欺的情绪冲击必须成立。
- **公平规则**：早早暗示"她未必百分百可靠"；线索靠正常游玩可得，不要藏在晦涩操作后；
  **不要事后用反转抹掉玩家有意义的选择**。
  → 本作是**天然的不可靠叙述结构**：玩家全程只听得到她一个人的转述，
  而"她未必听你的"本身就是关系层面的不确定性。这条线几乎是白送的剧情纵深（§2.2）。

### 1.5 上古卷轴世界观考据（为剧情扩充提供素材）

- **奥杜因不是纯反派**：他是阿卡托什长子、"世界吞噬者"，职责是终结旧纪元以便新纪元开始；
  他"贪婪地"想统治而非完成职责，才变得可被击败。
  （<https://narrativeatlas.studio/blog/the_elder_scrolls/elder-scrolls-lore-beginners-guide>、
   <https://www.thegamer.com/elder-scrolls-skyrim-plot-lore-explained/>）
  → 本作 `end-thu-um` 里"把蛋还给它、它把她当同类、往北回到蛋那儿"**已经非常贴合这个设定**，
  说明作者对 lore 是有理解的，值得顺着这条线深挖，而不是写成简单打龙。
- **刀锋会 vs 灰胡子的哲学冲突**：前者视龙吼为对抗龙的武器（并要求杀帕图纳克斯），
  后者视其为修行与崇拜之道。（同上）
  → 本作 `end-thu-um` 借阿尔卡之口说"诺德人当年不是杀，是谈判"，站的是灰胡子一侧。
  可以把这个冲突做成一个**真正的阵营抉择**，而不是只写在结局旁白里。
- **梭摩 / 白金协定**：禁止崇拜塔洛斯、裁判决（Justiciar）如秘密警察般行动；
  其动机是形而上学层面的"解除凡人成神之约"，是"哲学上有趣的反派"。
  → 本作第四章已有帝国线 / 风暴斗篷线，但**完全没有梭摩**。加入第三股压力能让政治两难升级。
  （<https://eathealthy365.com/understanding-the-backstory-and-lore-of-skyrim/>）
- **帕图纳克斯的两难**：他曾是奥杜因副手、犯下暴行，后来叛变教人类龙吼；杀不杀他
  在原作里"零机制后果、社区争论十五年"。
  → 反面教材：**纯道德选择若不影响任何系统，就会变成空转**。本作若要加类似抉择，
  必须让它落进 `flags` / `end-select` 门槛。

## 二、剧情扩充提案

### 2.1 补坑优先：`end-dragon-slayer`（P0，纯数据）

`docs/design.md` §七已列为待办。现状第三章有 `ch3-dragon-win`（它倒了），
但它和 `ch3-dragon-lose` / `ch3-dragon-flee` 一样汇入 `ch3-after-dragon`，
**打赢了也没有独立结果**——这与"选择必须有分量"直接冲突。

提案：在 `ch3-dragon-win` 后加一个 2–3 场景的短藤蔓：

- 她吸了龙的魂（Dragonborn 设定），肋上的火变了 → 新 flag `flags.absorbedSoul`；
- 阿尔卡/灰胡子式的声音通过水晶说话："你现在是它们的一员了"；
- 二选一：把龙魂交给"刀锋会式"人物（换一件实物 + 一条政治线），
  或留下（打开隐藏结局门槛）。
- 结果**必须汇回 `ch3-after-dragon`**，只改变过程状态，不复制下游（藤蔓纪律）。

门禁影响：新 flag 需在 `dse.yml:initial.flags` 预声明；新结局要进 `end-select` 与
`tests/e2e_cases.json`（用 `solve_e2e.py --all --write-cases` 重建）。

### 2.2 海尔根真相："不可靠叙述者 + 记忆回廊"（P1，纯数据 + 现有 diary）

这是我最推荐的一条线，因为它**用的全是已有机制**（diary 模式、`clues`、`extraText`），
却能把主题从"生存"抬升到"你能否信任你唯一的声音"。

现状：序章有 `core-corridor`（记忆回廊），第二章有 `ch2-mage-truth`（那天晚上）
给出海尔根真相，`clues.helgenTruth` 是隐藏结局门槛之一。

提案做法：

1. **锚点场景分歧**：`core-corridor` 保持同一 ID，但正文用 `extraText` 按
   `flags.knewTruth` / `flags.refusedAdvice` 追加段落——
   同一段记忆，在"你曾劝她别去"和"你从未劝过"两种历史里，细节不同
   （火从哪边烧起来、她是不是自己走的）。玩家跨周目比对才发现。
2. **矛盾目击者**：酒馆的诺德人（`ch2-tavern`）与灰斗篷（`ch2-mysterious-woman`）
   对"那天城门口站着谁"给出互相冲突的说法；`clues.helgenTruth` 不是一次获得，
   而是靠**两处互相印证的线索**才置真。
3. **公平规则**：第一次矛盾要在第二章中段就出现（早早 signal），
   并在 `diary` 里给玩家一个可回看的"互相冲突的两句话"条目；
   不要在终局突然反转抹掉之前的选择。
4. **情感真相**：无论玩家是否拼出时间线，`end-mercy` / `end-refused` 的
   "她其实一直想问你'你觉得呢'"都要成立。

### 2.3 第三势力：梭摩裁判官（P1→P2，中等数据量）

现状第四章是帝国线 / 风暴斗篷线两条，阿尔卡在结局里"烧纸"（守墓人家、烧的是纸）。
把"烧的纸"坐实为**塔洛斯崇拜者名单**，让梭摩裁判官成为真正的第三方压力：

- 第二章 `ch2-faction-brief` 增加一段"两面旗之外的第三面旗"——有人在看，但不属于任何一方；
- 第四章两条政治线各自多一个"如果交出名单/烧掉名单"的分支，落进 `flags.keptSecret`；
- 新的失败结局 `end-justiciar`（被带走），或让 `end-soldiers` 从"被举报告发"
  升级为"举报者到底是谁"的揭示。

设计价值：原作内战两难是"都没有正确答案"；加入梭摩后，玩家会意识到
**自己之前在两条旗之间的all-in 可能从一开始就是伪命题**——这是系统层面的反讽。

### 2.4 把"阿尔卡"从结局道具变成角色（P1）

阿尔卡目前只在 `end-whiterun` / `end-mercy` 的尾声出现（守墓人、烧纸、北行、带箱子），
是典型的"麦高芬"。但他承载了全作最好的情感钩子："她带了一个人来" / "他一直在我脑袋里指挥我，烦死了"。

提案：在他真正出场**之前**，先让"一个在烧纸的人"作为传言出现三次
（第一章渡口索恩的闲话、第二章酒馆、第三章大殿的纸灰），
每次只给一个细节；到真结局时，玩家把三个细节拼起来才明白那是同一个人。
这是"埋伏笔且事后必然"的经典手法，成本只是三处 `extraText`。

### 2.5 可选大改：玩家身份与"水晶的另一端"（P2，慎用）

`end-mercy` 里"第二天**你**去了白漫"——玩家第一次从纯声音变成行动者。
可以把"你是谁"做成贯穿全作的暗线（法师？被派来的人？阿尔卡旧识？），
在关键 dialogue 节点用 `clues.*` 逐步揭示。

风险：玩家角色一旦具体化，就会削弱"你只是个声音"的留白美感
（Lifeline 原作者刻意让主角无性别、把玩家留在幕后）。**建议作为可选 DLC 而非主线**。

## 三、机制扩充提案（按落地代价分层）

### 3.1 P0-A：让信任真的决定"她听不听"（纯数据，必须做）

**问题**：`00-core.yml` 里 three advice 选项的权重分别是 7/3、6/4、4/6——
只取决于你选了哪句话，**与 `trust` 完全无关**；
引擎 `_pick_weighted` 只接数字字面量（`engine.py:324`），不支持表达式。

**纯数据解法**（不需要改引擎）：用 `if` 门控的"重复选项组"模拟动态权重——

```yaml
# 概念示意（非最终写法）
core-advice-2:
  choices:
    - text: 「……」
      if: 'trust >= 70'
      goto: [{to: obey-strong, weight: 9}, {to: defy-strong, weight: 1}]
    - text: 「……」          # 同一句话，低信任版本
      if: 'trust < 70'
      goto: [{to: obey-weak, weight: 4}, {to: defy-weak, weight: 6}]
```

两条 `if` 互斥，玩家只会看到一句；高信任时她九成照做，低信任时六成违抗。
这样 `trust` 首次成为**实时可感的机制**，而不只是结局门槛（现在只用于 `end-select`）。
另需在 `stats` 输出或 `diary` 里给一个软提示（"她今天好像更愿意听"），让玩家学得会。

代价：每个关键建议点多一组场景；必须用"汇回同一后继"控制藤蔓。

### 3.2 P0-B：soul 归零后果化（纯数据 + 可选 fatal）

README 说"归零即通讯断绝"，但真结局终局 `soul=0` 仍圆满通关。两种补法：

- **软后果**（推荐，贴合原作）：soul 低时选项收敛——`if: soul >= 2` 才出现"深度咨询"类选项，
  低 soul 只剩安慰/沉默；`extraText` 描写信号变弱、字变少。这把抽象数字变成可感知的体验。
- **硬后果**（谨慎）：加 `fatal: soul<=0 and clock>=? → end-refused`，
  但这会**砍掉现有的惨胜真结局**，需重新验 8 结局可达性。除非想要更硬核，否则不建议。

### 3.3 P1：`clocks` 显性压力系统（纯数据 + UI 文案）

Citizen Sleeper 的启示：把隐性计数器变成**玩家看得见的时钟**。
本作已有 `clock`（夜深）、`warmth`（体温）、`soul`、`trust`，但只有 `warmth` 是明面死亡线。

提案：把 `clock` 重新定义为"追兵/风雪/龙醒"三条**并行时钟**，
在 `stats` 输出和 `diary` 顶部用文字呈现（无需新 mode）：

```
夜深 17 | 风雪 —— 逼近 | 追兵 —— 城门 | 龙 —— 醒着
```

每条时钟在关键场景 `onEnter` 推进，到阈值时**改变已有场景的 `extraText` 和选项可见性**
（例如"追兵=城门"时 `ch4-water-gate` 才出现）。
这把"资源耗尽"从后台数字变成前台戏剧，且完全用现有 `if` / `extraText` 表达。

### 3.4 P1：`@loop` 记忆轮回（引擎已支持，纯数据）

**最大的未用杠杆**。`dse-core 0.7.0` 原生支持 `goto: '@loop:<scene>'`，
重置状态但保留 `loopKeep`（本作已配 `clues` + `flags`）。
这正好把《生命线》的 Rewind 从"事后回退几步"升级为**叙事装置**：

- 场景设计：某个节点（如 `ch2-mage-truth` 之后）提供"再过一次这一天"的出口，
  状态重置、体温/金币/体力复原，但 `clues.*` / `flags.*` 保留——
  **她不记得重来过，你记得**。
- 剧情价值：玩家用上一轮的失败知识，这一轮走不同的路；
  "知识即选项"从口号变成结构性玩法。配合 §2.2 的不可靠叙述，
  轮回后的记忆回廊细节不同，暗示"她其实也隐约记得"。
- 风险：循环必须是**有限、可退出、收敛**的——
  引擎有 `max re-visits`（CLI `--max-revisit` 缺省 3）作防御；
  `verify.py` 的 fuzz 步进上限 80 已能兜住活锁，但加循环后**必须重跑门禁**确认覆盖率不塌。
  需要给玩家明确的"这是第几次"标记（`diary` 里加轮次条目）。

### 3.5 P1：成就从 6 条扩到 12–14 条（纯数据）

现有 6 条都绑定关键节点（`dse.yml:191-217`）。可加：
- 第一次拒绝（`flags.refusedAdvice`）
- 集齐全部 `clues.*`（复合 `when`，需确认引擎 `when` 支持 `and` 或多个 flag——目前写法是单表达式，`when: 'clues.soulLink and clues.helgenTruth'` 应可行，需实测）
- 每一条结局一个成就（8 条）
- 完成一次轮回（新 flag `flags.looped`）

### 3.6 P2：外部知识谜题（谨慎，借鉴 Lifeline 的辐射查询）

Lifeline 原作有个名场面：角色问玩家"睡在多强的辐射旁是否安全"，
要求玩家**到游戏外查资料**。搜索文献指出这个设计因搜索结果被剧透帖污染而打了折扣。

本作已有"知识即选项"的雏形（`clues.nordCustom`、`clues.thuUm`），
可以在 `diary` 里放一段**考据式线索**（例如诺德丧俗或龙语词根的真设定），
让玩家把它和场景里的描述对照后选对答案。
前提：线索必须在**游戏内**可查（避免 Lifeline 的剧透坑），且不阻塞主线。

### 3.7 明确不建议的方向

| 方向 | 为什么不做 |
|---|---|
| 自定义 mode（如"审讯""解谜"） | Scene Schema 封闭、`additionalProperties: false`，`dse check` 直接打回（`design.md` §二已验证） |
| 动态权重表达式 `weight: trust/10` | 引擎只接受正数 int/float，会运行时报错；用 §3.1 的 if 门控替代 |
| 大地图 / 装备树 / 语音 | 与"对话核心"无关，Short 明确批评这类元素稀释体验 |
| 频繁即时死亡 | 违背 Lifeline "死亡常见但 Rewind 免费"的地基，且 Short 指出即时死亡与代入感冲突 |
| 引入 LLM 实时生成台词 | 破坏固定 e2e 输入流、四层门禁与可复现录制（本仓的核心工程资产），且不可审校 |

## 四、门禁与工程影响（每次改内容都要做）

1. 任何 `content/*.yml` 改动 → `python tools/verify.py` 四层门禁必须重跑；
2. 选项编号漂移 → `python tools/solve_e2e.py --all --write-cases`
   重建 `tests/e2e_cases.json`，否则 8 条 e2e 全错位（这是 0.7.0 升级时踩过的坑）；
3. 新 flag/clue → 必须在 `dse.yml:initial` 预声明，否则 `if` 静默判 False；
4. 新结局 → 进 `end-select` 分流 + coverage 门 + e2e + 8 结局全量导出；
5. 加 `@loop` → 重点观察 fuzz 覆盖率与步进上限，确认不活锁、不覆盖塌陷；
6. 遵守藤蔓结构：支路 1–2 跳汇回，不为"丰富"复制下游（否则路径数指数爆炸）。
